PART 5 — CORE BACKEND METHODS AND BUSINESS RULES
--------------------------------------------------------------------------------
AUTH AND TOKENS
  * Demo OTP is generated server-side and returned in the response for local
    walkthroughs; production would need SMS/email delivery.
  * Tokens are stateless HMAC JSON blobs with 24h expiry. deps.py strictly parses
    Bearer tokens, rejects non-HS256 algorithms, verifies sub/role claims, allows
    role member/admin only, and permits 30s clock skew.
  * localStorage keys: mt for member, at for admin; tokens are sent in headers,
    not cookies. No refresh, logout endpoint, or server-side revocation.

ELIGIBILITY (order matters)
  1. Admin override -> Approved ("manual review").
  2. Cool-off: 90 days from last quality-passed completion -> Rejected with date.
  3. Survey status != live -> Rejected ("not open").
  4. Deadline passed -> Rejected ("closed on ...").
  5. Quota reached -> Rejected; quota counts only quality-passed completions.
  6. Rules: strict failure rejects immediately; flexible failures are collected.
  7. Any flexible failure -> Waitlisted with "Ops may still approve you".
  8. Otherwise Approved.
  * Every evaluation is persisted in eligibility_results via app-level upsert.
  * Fail-closed (SEC8): exceptions return Rejected / "System error — please retry".

REFERRAL + PAYOUT PIPELINE
  * Stages: Lead -> Fit -> Completed / Failed.
  * Completed is irreversible (409 if repeated).
  * Failed requires a failure reason (422 otherwise).
  * Completed requires survey_id and rejects duplicate completions.
  * Quality-passed completion creates Completion + member payout(survey.amount) +
    referrer bonus payout (REFERRAL_BONUS, default 100), idempotent per referral.
  * Every payout receives a unique UTR at creation; startup backfills older rows.
  * Quality-failed forces Failed with reason and no payouts.
  * Payout status: Pending -> Approved -> Paid; skipping Approved is 409.
  * Batch approve accepts explicit IDs or all Pending, returns count and total.

FRAUD
  * duplicate_signup flagged on duplicate phone.
  * self_referral flagged when referrer phone == referred phone.
  * burst_signups flags >=3 signups from same IP or device within 24h; loopback
    and non-IP strings are excluded.
  * referral_ring detects cycles in referrer graph.
  * Flags are idempotent while open and never deleted; status moves to
    Cleared or Confirmed. scan() is retroactive and idempotent.
  * Imported rows lack IP/device, so only ring scan can flag them.

CSV IMPORT
  * Accepts 10 date formats with 2-digit-year pivot; rejects impossible/future dates.
  * Income normalized to <5L / 5-10L / 10L+ with warnings.
  * Gender m/f/female normalized.
  * Detects in-file and cross-DB duplicate phones.
  * Unknown free-text sources auto-created with type imported and unique slugs.
  * referred_by resolved in a second pass; self-referral and missing referrer warn.
  * joined_on becomes member.created_at; last_survey_completed_on creates a
    Completion with nullable survey_id and starts the cool-off.
  * dry_run writes nothing; commit is one transaction; details[] explains fixes.
  * SEC5 neutralizes leading = + - @ in free-text cells with an apostrophe to
    stop spreadsheet formula injection; phone/date fields are excluded.

RULE SUGGESTION
  * POST /api/admin/suggest-rules calls an OpenAI-compatible chat/completions
    endpoint when LLM_API_KEY is configured (default gpt-4o-mini, temp 0,
    15s timeout, strict JSON array prompt).
  * Any failure falls back to _heuristic(): age regex, 30-city list, gender
    keywords, income ranges.
  * _validate() filters candidates through RuleIn; nothing is persisted until
    an admin explicitly saves via POST /api/admin/surveys.

META LEADS
  * POST /api/meta/lead dedupes by lead_id and stores raw payload JSON.
  * Per-campaign and per-ad stats power the admin Meta Leads screen.
  * SEC3 enforces Meta HMAC X-Hub-Signature-256: sha256=<hex> via
    hmac.compare_digest when META_WEBHOOK_SECRET is configured; old
    X-Webhook-Token path was removed; missing secret remains an explicit dev-open
    path with a warning.

GOOGLE FORMS
  * POST /api/admin/surveys creates a matching Google Form titled after the survey.
    With GOOGLE_SERVICE_ACCOUNT_JSON the live Forms API creates name/phone/city/
    email questions; without credentials a local mock responder link is stored and
    google_form_mode records "live" or "mock" (the UI also handles legacy "demo").
  * 2026-11-27: live form creation now requests forms.body + drive.file scopes and,
    after creation, shares the file as a reader with every comma-separated email in
    GOOGLE_FORM_SHARE_WITH. Sharing failures are warnings only; the form still works
    for the service account. README/.env.example now explain enabling Forms + Drive
    APIs, sharing the Sheet with the service account, and the one-line JSON key.
  * POST /api/google-forms/lead accepts {response_id, form_id, fields} and now also
    accepts an explicit survey_id. It normalizes phone/name/city/email, dedupes by
    response_id, links by survey_id first and google_form_id second, creates a minimal
    Member + Referral for valid responses, and writes a GoogleFormLead row with
    source "Google Form".
  * Invalid/unlinked responses are still stored with status "needs review" and the
    endpoint returns 422 with a safe reason.
  * Every ingest/sync rewrites data/google_form_leads.xlsx (or
    GOOGLE_FORM_XLSX_PATH). POST /api/admin/google-forms/sync pulls from a linked
    Google Sheet when credentials + GOOGLE_FORM_RESPONSES_SHEET_ID exist; if those
    are absent it falls back to data/google_form_responses.csv (override with
    GOOGLE_FORM_RESPONSES_LOCAL_PATH). In local mode a survey_id column can target a
    survey directly and, if there is no linked survey, the first survey is used.
    Genuine Sheet/API errors are not hidden by the fallback: they still surface as
    FormsError/502. The response now includes mode, synced, duplicates, failed,
    errors, and xlsx.
  * GOOGLE_FORMS_WEBHOOK_SECRET enables HMAC verification via
    X-Google-Forms-Signature-256: sha256=<hmac-sha256 of raw body>.
  * The bundled data/google_form_responses.csv has 2 local demo responses
    (local-demo-response-001/002) so the sync button works with zero configuration.

RATE LIMITS

  * SEC4 extracted RateLimiter / InMemoryRateLimiter / RedisRateLimiter with

  * .env.example documents RATE_LIMIT_BACKEND=memory|redis and WEB_CONCURRENCY.

AUDIT / LOG HYGIENE

  * SEC9 strips CR/LF, redacts sensitive keys, and masks 10-digit phone numbers

SECURITY HEADERS / CORS
