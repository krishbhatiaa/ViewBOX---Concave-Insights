ELIGIBILITY (eligibility.py, 55 lines) — check ORDER:
  1. admin override        -> Approved ("manual review")
  2. cool-off (90d from last quality-passed completion) -> Rejected (+date)
  3. survey.status != live -> Rejected ("not open")
  4. deadline passed       -> Rejected ("closed on {date}")
  5. quota reached (counts ALL completions) -> Rejected ("reached its quota")
  6. rules: strict fail -> immediate Rejected; flexible fail -> collect
  7. any flexible fails -> Waitlisted (+ "Ops may still approve you")
  8. else Approved
  GAP: quota counts non-quality-passed completions; cool-off counts only
       quality-passed — asymmetric. survey.status is immutable after creation
       (no edit/close endpoint), so check 3 is effectively dead code.
  COOL_OFF_DAYS = 90. record_result() upserts eligibility_results in app code.

REFERRAL PIPELINE (services/referral.py)
  set_stage(): Completed is IRREVERSIBLE (409); Failed requires reason (422);
  Completed requires survey_id (422) + no duplicate completion (409);
  quality passed -> Completion + payout(survey.amount) + referrer bonus payout
    (REFERRAL_BONUS env, default 100, idempotent per referral);
  quality FAILED -> forced Failed + reason + NO payouts.
  Bonus = flat 100. Payout.status: Pending -> Approved (gate) -> Paid (409 if skip).

FRAUD (fraud.py)
  Flag types: duplicate_signup (from auth.py), self_referral, burst_signups
              (IP or device, >=3 in 24h, BURST_MIN=3), referral_ring (cycle detect).
  add_flag is idempotent (no dup while open); flags NEVER deleted (open -> Cleared|Confirmed).
  loopback/non-IP strings never burst-flag. scan() is retroactive + idempotent.
  GAP: imported CSV rows never run on_signup (no ip/device), so only ring scan
       can ever flag them, and only via manual POST /fraud/scan.
  GAP: _burst_flags is O(n^2); _ring_flags loads all members.

CSV IMPORT (services/importer.py, 206 lines)
  10 date formats + 2-digit-year pivot (rejects <=1920 or future, never guesses);
  income mapped to 3 buckets (<5L/5-10L/10L+) with warn; gender m/f normalised;
  in-file AND cross-DB duplicate phone detection; unknown sources auto-created
  (type 'imported'); referred_by matched in second pass (self-referral -> warn,
  missing referrer -> warn 'not imported'); joined_on -> member.created_at;
  last_survey_completed_on -> Completion(survey_id=null) -> starts cool-off;
  dry_run previews and writes NOTHING; single commit; per-row details[] report.
  Tested against the REAL data/viewbox_respondents_sample.csv (189 rows).

LLM RULE SUGGESTION (services/rule_suggest.py, Tier 3 choice (b))
  _llm(): OpenAI-compatible chat/completions (LLM_API_KEY, default gpt-4o-mini,
          temp 0, 15s timeout, strict JSON-array prompt); returns None on any
          failure -> _heuristic() keyword fallback (age regex, 30-city list,
          gender keywords, income ranges). _validate() filters through RuleIn.
  NEVER persists — admin must save via POST /api/admin/surveys.
